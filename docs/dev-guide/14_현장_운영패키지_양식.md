# 14. 현장 운영 패키지 양식 — 강사용 1장 · 학생 활동지

앱만으로는 수업이 안 된다. 체험관에서 강사들이 실제로 들고 다닌 건 **강사용 안내 1장**과 **학생 활동지 1장**이었다.
앱 하나마다 이 두 가지를 같이 만든다. 견본은 체험관 것:

| 견본 | 파일 |
|---|---|
| 강사용 | `docs/운영자_사용설명서.html` (→ PDF) |
| 학생 활동지 | `docs/학생_활동지.html` (→ PDF, A4 1장) · `docs/학생_활동지.pptx` (고칠 수 있는 판) |
| 활동지 PPT 를 만드는 스크립트 | `tools/make_worksheet_pptx.py` |

## 1. 앱마다 내는 것

| 파일 | 필수 | 형식 |
|---|---|---|
| `docs/topics/tNN_강사용.html` + `.pdf` | ○ | A4 세로, 1~2장 |
| `docs/topics/tNN_활동지.html` + `.pdf` | 활동지가 있는 수업이면 ○ | A4 세로, **딱 1장** |
| `docs/topics/tNN_활동지.pptx` | 권장 | 학교 선생님이 고쳐 쓸 판 — HTML 과 **같은 내용** |

PDF 는 손으로 인쇄해 만들지 않고 도구로 만든다(§5). 이름은 위와 똑같이 — 검사기가 `docs/topics/tNN*` 만 이 앱 파일로 본다.

## 2. 강사용 1장 — 이 순서로

강사는 **수업 5분 전에 이것만 읽고** 들어간다. 앱 기획서(11 문서)는 개발자용이고, 이건 현장용이다.

```
┌ tNN 제목 ─ 차시 ─ 한 줄 목표 ───────────────────────────────┐
│ 1. 준비물·준비        태블릿·로봇 수, 코스·매트·종이, 배터리 확인, 앱 버전(v1.0.xx 이상)
│ 2. 수업 흐름 (분)     도입 5 · 활동 ① 10 · 활동 ② 15 · 정리 5 — 각 단계에서 강사가 할 말 한 줄
│ 3. 화면별로 할 일     앱 화면 그림(작게) + 학생이 누르는 것 + 강사가 볼 것
│ 4. 막힐 때            증상 → 바로 할 일 (3~6개, 현장에서 실제로 물어본 것)
│ 5. 안전               로봇을 책상 끝에서 떨어뜨려 두기, 손 끼임, 멈춤 버튼 위치
│ 6. 기록               이 앱이 성장기록부에 남기는 것 (t15 에서 모인다)
└──────────────────────────────────────────────────────────────┘
```

- **막힐 때**는 지어내지 않는다. 처음엔 공통 3개(아래)로 시작하고, 시범 수업에서 실제로 나온 걸 더한다.
  - 연결이 안 돼요 → 상단 🔗 → 목록에서 **로봇 스티커 번호**(BF16) 선택. 페어링은 필요 없다. 다른 태블릿의 짝이면 🔓 짝 해제.
  - 자꾸 끊겨요 → **배터리**(🔋 칩 빨강이면 교체·충전)가 1순위(03 §7).
  - 로봇이 이상하게 움직여요 → `■ 멈춰` → 차를 바닥에 내려놓고 다시. 그래도 이상하면 다른 로봇과 바꿔 앱 문제인지 차 문제인지 가린다(04 #36).
- 문장은 짧게, 강사가 학생에게 **그대로 읽어 줄 수 있는 말**로.

## 3. 학생 활동지 1장 — 양식

- **A4 세로 1장.** 여백 위·아래 20mm, 좌·우 11mm → 그릴 수 있는 영역 **188×257mm ≈ 711×971px**.
  화면에서 보지 말고 이 폭으로 재야 한다 — 1280px 화면에서 '한 장'이던 게 인쇄하면 두 장이었다(04 #39).
- 견본 `docs/학생_활동지.html` 을 `docs/topics/tNN_활동지.html` 로 복사해 시작한다. 뼈대:

  | 부분 | 클래스 | 내용 |
  |---|---|---|
  | 머리 | `.head` | 제목(이모지 1개) · 부제 · 경남수학문화관 로고 |
  | 리본 | `.ribbon` | 활동 단계 ①②③④ — 앱의 단계 표시(05 §7)와 **같은 이름** |
  | 이야기 | `.story` | 2~3줄 상황 (왜 이걸 하나) |
  | 단계 카드 | `.step` | 단계마다: 할 일 → 잰 값 쓰는 칸 → 계산 칸 → `.hint` |

- 색은 05 §1 의 변수 색, 글꼴 Esamanru(PPT 는 맑은 고딕 — §4).
- **빈칸은 정수가 나오게.** 잰 값을 쓰게 하면 '나누는 수의 배수로 반올림해서 쓰기'처럼 계산이 떨어지게 한다(03 §3).
- **용어를 정확히.** ÷2 가 아닌 걸 '평균'이라 부르지 않는다(04 #32). 3~4학년이 아는 말로.
- 앱 화면의 버튼 이름·단계 이름과 활동지 글자가 **똑같아야** 한다(앱을 고치면 활동지도).
- 견본에는 이름 칸이 없다 — 체험관에서 '내 로봇 번호·모둠' 칸이 필요 없다고 해서 뺐다. 학교 수업에서 필요하면 모둠 이름 한 칸만 넣는다.

## 4. 고칠 수 있는 판 (PPT)

학교마다 선생님이 문구를 바꿔 쓰고 싶어 한다. PDF 는 못 고치므로 PPT 를 같이 준다.

- `tools/make_worksheet_pptx.py` 가 견본 활동지를 **진짜 글자·진짜 표**로 만든 예다. 복사해서
  `docs/topics/tNN_make_pptx.py` 로 바꿔 쓰거나, 파워포인트에서 직접 만든다.
  ```bash
  pip install python-pptx
  python3 tools/make_worksheet_pptx.py        # → docs/학생_활동지.pptx (견본)
  ```
- 글꼴은 **맑은 고딕**(한국 윈도우 기본) — 다른 PC 에서 열어도 줄이 안 밀린다.
- 그림으로 붙여 넣지 않는다(글자를 못 고친다). 빈칸은 '밑줄 친 공백'으로 — 그 자리에 바로 타이핑할 수 있다.
- HTML 을 고치면 PPT 도 고친다. 두 판의 문구가 다르면 현장에서 혼란이 생긴다(`docs/활동지_고치는법.md`).

## 5. PDF 만들기·확인

```bash
node tools/make_pdf.mjs docs/topics/t07_활동지.html --pages 1   # 1장을 넘으면 ❌
node tools/make_pdf.mjs docs/topics/t07_강사용.html              # 몇 장인지 알려 줌
```
- 인쇄와 같은 방식으로 그리고, 글꼴·로고가 HTML 옆에 없으면 `webapp/fonts/`·`webapp/assets/` 에서 찾아 쓴다.
  `⚠️ 없는 파일` 이 나오면 그 그림이 PDF 에서 빠진 것이다.
- HTML 을 고치면 **PDF 를 다시 만든다.** HTML 만 고치고 PDF 를 그대로 두면, 현장에는 옛 PDF 가 나간다.
- 마지막으로 **진짜 프린터로 한 장** 뽑아 본다(프린터마다 여백이 다르다).

## 6. 운영 수칙 — 모든 앱 공통 (강사용에 그대로 옮겨 써도 된다)

1. **태블릿 1대 = 로봇 1대 = 한 모둠**, 32차시 내내 같은 번호. 태블릿과 로봇에 같은 번호 스티커.
   - 모둠 이름·성장기록부는 **태블릿에** 저장된다. 수업 중 모둠끼리 태블릿을 바꾸면 기록이 섞인다(10 §6).
   - 같은 태블릿을 여러 반이 쓰면 반마다 기록이 겹친다 → 반이 바뀔 때의 처리(태블릿 나누기 / 기록 내보내기)는
     t15 기획에서 정한다(10 §7).
2. **수업 전 배터리** — 로봇을 켜서 🔋 칩 확인. 낮으면(빨강) 교체. 끊김의 1순위 원인이다.
3. **업데이트는 덮어쓰기만** — 앱 홈의 업데이트 확인. **앱을 지우고 다시 깔지 않는다**(저장된 기록·짝·보정이 다 사라진다, 06 §5-3).
4. **새 모둠이 같은 앱을 시작할 때** — 앱의 `처음부터` 버튼.
5. **로봇은 바닥이나 매트 위에서.** 책상 위에서는 끝에서 떨어뜨려 두고, 자율 동작 중에는 손을 대지 않는다. 멈출 땐 화면의 `■ 멈춰`.
6. **현장 조건은 수업 전에 확인** — 창가 자리는 조도가 다르고(04 #38), 코스·매트는 학교마다 다르다. 앱이 가정한 조건과 다르면 그 자리에서 다시 잰다.
