# 02. 통신 규약 — "이미 해결됐으니 건드리지 마세요"

BLE 통신은 태블릿 12대 + 로봇 12대 동시 운영 현장에서 여러 번 무너지고 다시 세운 끝에 지금 상태가 됐다.
**주제 앱은 이 문서 내용을 직접 구현하지 않는다 — 전부 `kit.js` 가 한다.**
이 문서는 "왜 그렇게 되어 있는지"와, 통합 담당자가 kit 을 고칠 때 지켜야 할 것을 적는다.

## 1. 대원칙: 연결의 주인은 네이티브, 앱은 kit 을 통해 손님

- 연결·재연결·짝·좀비링크 감지는 **APK(`AltinoBle.kt`)** 가 한다.
- 웹 쪽에서 그걸 이어받아 쓰는 일은 **kit** 이 한다.
- 주제 앱이 하면 안 되는 것 (검사기가 잡음):
  - ❌ `AltinoNative.*` · `AndroidBridgeTransport` · `connectTo` 직접 호출
  - ❌ 재연결 타이머 만들기 — 네이티브의 '포기 없는 재연결'과 서로 방해한다
  - ❌ 연결 상태를 자체 변수로 추측 — `kit.connected` 와 `onStatus` 만 믿는다

## 2. 화면에 들어올 때 (kit 이 함)

```
연결이 살아 있음 (getState().connected) → adopt()      이어받기만, 재연결 아님
짝이 있음        (getState().address)   → connectTo(그 주소)
아무것도 없음                           → 연결창 열기
```
이걸 빼먹으면 학교 화면에서 연결하고 앱에 들어갔을 때 연결이 끊기거나 엉뚱한 로봇에 붙는다(04 #3).

## 3. 1:1 짝 잠금 (kit 이 함)

- 로봇을 한 번 고르면 그 로봇과 **짝**이 되어 저장된다(앱을 다시 켜도 유지).
- 자동 재연결은 **그 로봇만**. 연결창에서 다른 로봇은 흐리게 + 🔒, 눌러도 안 붙는다.
- 바꾸려면 연결창의 **🔓 이 태블릿 짝 해제**(확인창을 거침) → 새로 선택.
- 12초 넘게 재연결이 이어지면 kit 이 **짝지은 차 번호와 푸는 법**을 알려 준다(04 #35 — 파일럿 "4번 연결 안 됨").

## 4. 연결창 표시 (kit 이 함)

- 큰 글씨는 **로봇 스티커 번호** `⟨BF16⟩` — BLE 이름 `ALTINO-NBF16` 에서 뽑는다(`kit.stickerCode`).
- ❌ MAC 뒤 4자리를 크게 보여 주지 않는다 — 스티커와 달라 현장이 혼란에 빠졌다(04 #6).
- 표시: `· 가장 가까움`(신호 1위), `· 내 짝 ✓`, `· 🔒 짝 해제 필요`.

## 5. 전송 규칙

| 항목 | 값 | 이유 |
|---|---|---|
| 주기 | **100ms (10Hz) 고정** | 20Hz 면 12대 합산 트래픽이 두 배 → 명령이 씹힘(04 #2) |
| 프레임 | `AltinoProtocol.buildFrame(state)` 만 | 체크섬·인코딩 직접 구현 금지 (음수 모터값 인코딩 함정 — 03 §9) |
| 조작 | 앱은 '무엇을 하라'(`kit.drive`)만, 전송은 kit 루프가 | 이벤트마다 보내면 큐가 밀린다 |
| 정지 보장 | 화면 이탈·창·센서 끊김에서 즉시 정지 | 12 문서 S1·S2·S6 |

## 6. 센서 수신

- 조각난 바이트를 54바이트 프레임으로 맞추는 건 `SensorFrameAssembler`(kit 안). 직접 파싱 금지.
- 앱은 `onSensor(s)` 로 받는다 — 10Hz.
- **화면 숫자는 200ms 마다만 갱신** + 고정폭 칸(`font-variant-numeric: tabular-nums; min-width`) — 숫자가 덜덜 떨리면 정신없다(04 #14).

## 7. 상태 문자열

`onStatus(base, raw)` 의 `base` = `raw.split(':')[0]`.

| raw | 뜻 | kit 의 화면 처리 |
|---|---|---|
| `connected` | 연결 완료(알림 설정까지 끝) | `🔗 연결됨 ✓` |
| `connecting` | 연결 시도 중 | `🔗 연결 중…` |
| `reconnecting:N` | N번째 자동 재연결 | `🔗 재연결 중…` — 기다리면 됨. 12초 넘으면 원인 안내 |
| `disconnected:normal/timeout/remote/gatt-error/stale/connect-timeout/…` | 끊김(사유별) | `🔗 연결 끊김` — 곧 reconnecting 이 옴 |
| `error:bluetooth-off` | 블루투스 꺼짐 | 그대로 표시 |
| `error:location-off` | 위치 꺼짐(일부 기기는 스캔 불가) | 〃 |
| `error:no-bound` | 짝 없이 연결 시도 | 〃 |
| `scanning` | 스캔 시작(진행 알림) | 표시 안 함 — **연결 끊김으로 취급하면 안 된다**(04 #26) |

## 8. 네이티브가 알아서 하는 것 (참고)

- 끊기면 지수 백오프 + 지터로 **포기 없이** 재연결, 2회부터 OS 배경 재연결.
- '연결됨인데 8초 무응답' 좀비 링크 → 강제 재연결.
- 블루투스를 껐다 켜면 자동 복구. 위치 꺼짐 경고. 스캔 횟수 제한 회피.
- 명령 직렬 큐 + **최신 프레임만**(밀리면 묵은 프레임은 버림). GATT 호출은 **전용 스레드**에서(04 #30).
- 권한을 방금 허용하면 스캔을 다시 건다.

## 9. 연결 담당 객체는 하나 (통합 담당자용)

`AndroidBridgeTransport` 를 여러 개 만들어도 **데이터·상태는 `_claim()` 한 하나에게만** 간다.
연결창의 스캔용 객체는 `_attach()` 만 하고, 닫을 때 `detach()` 한다.
예전엔 새 객체가 전역 콜백을 덮어써서, **연결창을 한 번 열면 센서 수신이 영구히 끊겼다**(04 #26).
kit 을 고칠 때 이 구분을 지킬 것.
