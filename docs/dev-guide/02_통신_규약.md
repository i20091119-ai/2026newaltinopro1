# 02. 통신 규약 — "이미 해결됐으니 건드리지 마세요" 목록

BLE 통신은 태블릿 12대 + 로봇 12대 동시 운영 현장에서 여러 번 무너지고
다시 세운 끝에 지금 상태가 됐습니다. **이 문서의 규칙은 전부 실제 사고의 재발 방지책**입니다.

## 1. 연결의 대원칙: 네이티브가 주인, JS는 손님

- 연결·재연결·짝(바인딩)·좀비링크 감지는 전부 **APK(AltinoBle.kt)가 담당**합니다.
- JS에서 하면 안 되는 것:
  - ❌ 재연결 타이머 만들기 (네이티브가 '포기 없는 자동재연결'을 함 — 이중 재연결은 서로 방해)
  - ❌ `window.AltinoNative.*` 직접 호출 (반드시 `transport.js`의 `AndroidBridgeTransport` 경유)
  - ❌ 연결 상태를 자체 변수로 추측 (`transport.connected`와 status 콜백만 신뢰)

## 2. 페이지 진입 시 `nativeStart()` 패턴 (필수, 템플릿에 포함)

```
연결이 살아있음(getState().connected) → adopt()   // 이어받기만, 재연결 아님
짝이 있음(getState().address)        → connectTo(그 주소)
아무것도 없음                        → 스캔 피커 열기
```

이 3분기를 빼먹으면: 홈에서 연결하고 앱에 들어갔을 때 연결이 끊기거나,
엉뚱한 로봇에 붙습니다. (실제 사고: 심화주차 앱이 이 패턴 누락 → 연결 미승계)

## 3. 1:1 짝(바인딩) 잠금 — UI까지 포함해서 필수

- 한 번 로봇을 고르면 그 MAC과 '짝'이 되어 저장됨(앱 재시작에도 유지).
- 자동재연결은 **그 로봇만** 대상. 스캔 목록에서 다른 로봇을 탭해도 붙지 않음
  (흐리게 + 🔒 표시, "짝 해제 먼저" 안내).
- 바꾸려면 반드시 `🔓 이 태블릿 짝 해제` 버튼 → unbind() → 새로 선택.
- **모든 앱의 연결창에 짝 해제 버튼이 있어야 함** (템플릿에 포함).
- 이유: 12대 부스에서 옆 태블릿 로봇을 실수로 뺏는 사고가 실제로 남.

## 4. 스캔 목록 표시 규칙

- 큰 글씨는 **스티커 번호** `⟨BF16⟩` — `stickerCode()` 헬퍼 사용 (BLE 이름 ALTINO-NBF16에서 추출).
- ❌ MAC 뒤 4자리를 전면에 표시 금지 — 로봇 몸체 스티커와 달라서 현장 혼란 (실제 사고).
- 배지: `· 가장 가까움`(RSSI 1위), `· 내 짝 ✓`(바인딩된 로봇).

## 5. 전송 규칙

| 항목 | 값 | 이유 |
|---|---|---|
| 스트리밍 주기 | **100ms (10Hz) 고정** | 50ms로 올리면 12대 합산 트래픽 2배 → 혼잡·끊김. 올리지 말 것 |
| 프레임 생성 | `AltinoProtocol.buildFrame(state)` 만 사용 | 체크섬·인코딩 직접 구현 금지 |
| 조작 방식 | state 객체만 변경, 전송은 스트리밍 루프가 | 이벤트마다 send() 남발 금지 (큐 밀림) |
| 정지 보장 | 화면 이탈(blur/hidden) 시 intent=0 | 손 떼도 달리는 사고 방지 (템플릿 포함) |
| 종료 시 | `state.stopAll()` 전송 후 disconnect | 소리·LED·모터 잔류 방지 |

## 6. 상태 문자열 사전 (status 콜백)

접두어로 분기: `String(s).split(':')[0]`

| 문자열 | 뜻 | UI 처리(표준) |
|---|---|---|
| `connected` | 연결 완료(알림 설정까지 끝) | `🔗 연결됨 ✓` (ok) |
| `reconnecting:N` | N번째 자동 재연결 중 | `🔗 재연결 중…` (pending) — 사용자는 기다리면 됨 |
| `disconnected:normal/timeout/remote/gatt-error/stale/manual/unbound` | 끊김(사유별) | `🔗 연결 끊김` (off) — 곧 reconnecting 옴 |
| `error:bluetooth-off` | BT 꺼짐 | "블루투스를 켜세요" |
| `error:location-off` | 위치 서비스 꺼짐(스캔 불가 기기 있음) | "태블릿 위치(Location)를 켜주세요" |
| `error:busy` | 연결 중 스캔 시도 | "연결 중(스캔 불가)" |
| `error:no-bound` | 짝 없이 connect() 호출 | "로봇을 먼저 선택" |
| `scanning` | 스캔 시작됨 | (무시 가능) |

전체 매핑은 템플릿의 `connErr()` 참고 — **문구도 통일**해 주세요.

## 7. 네이티브가 알아서 하는 것 (JS는 몰라도 됨, 참고용)

- 끊기면 지수백오프+지터로 **포기 없이** 재연결, 2회부터 OS 배경 재연결(autoConnect).
- '연결됨인데 8초 무응답' 좀비 링크 감지 → 강제 재연결.
- 블루투스 껐다 켜면 자동 복구. 위치 꺼짐 경고. 스캔 스로틀 회피.
- 명령 직렬 큐 + 최신 프레임 코얼레싱(밀리면 오래된 프레임은 버림).

## 8. 센서 수신

- `t.on('data', bytes => { for (const f of assembler.push(bytes)) onSensor(f); })` 패턴 고정.
- `SensorFrameAssembler`가 조각난 바이트를 54바이트 프레임으로 조립해 줌 — 직접 파싱 금지.
- UI 갱신은 **200ms 스로틀** + 고정폭 숫자칸(`tabular-nums`) — 숫자 떨림 방지 (표준).
