# 03. 알티노 NEO 하드웨어 실측 데이터집

부스 현장에서 실측·검증한 수치입니다. **각자 다시 실험하지 말고 이 표를 쓰세요.**
모든 제어는 `AltinoState`(state) 메서드로만 합니다.

## 1. 모터·조향

| API | 범위 | 실측 감각 |
|---|---|---|
| `state.go(m, m)` | -1000 ~ 1000 | 250=정밀조작, 300=순항, 350=활기참, 550=게임 최고단(체감 빠름), 후진은 -320~-350 |
| `state.steer(v)` | -127(좌) ~ 127(우) | ±100=일반 회전, ±127=풀락(제자리급 회전, K턴용) |

- `go(a, b)`는 좌/우 바퀴 개별 제어지만 **일반 주행은 같은 값**을 넣으세요. 회전은 steer로.
- 급출발이 부담스러운 활동은 150~250 권장. 550 초과는 체험용으로 비추(제어 불능감).

## 2. 적외선/TOF 거리 센서 — ⚠ 작을수록 가까움!

| 필드 | 위치 | 비고 |
|---|---|---|
| `ir1` | 전면 좌(대각) | |
| `ir2` | 전면 중앙 | 거리 활동의 기본 센서 |
| `ir3` | 전면 우(대각) | |
| `ir4` | 우측면 | 벽 따라가기용 |
| `ir5` | 좌측면 | |
| `ir6` | 후면 | 꼬리잡기 '붙음' 판정에 사용 |

**스케일 (실측):**

| 상황 | 값 |
|---|---|
| 완전 개방(벽 없음) | ≈ 1300 |
| 5cm 앞 장애물 | ≈ 60 |
| 유효 측정 한계 | ~900 (이보다 크면 "벽 없음"으로 취급 권장) |

**검증된 임계값 (n자 코스 완주 세팅):**

| 용도 | 값 |
|---|---|
| 정면 회피 시작 (ir2) | **160** |
| '코앞'(후진 필요) | 정면값 × 0.55 (동적 계산) |
| 전면 대각 끼임 (ir1/ir3) | 70 미만이면 끼임 → 후진 탈출 |
| 측면 긁힘 직전 (ir4/ir5) | 75 (강긁힘 90) |
| 후면 '붙었다' 판정 (ir6) | 50 미만 (120은 오검출 심함) |
| 주차 목표 거리 후보 | 90~200 (70 미만은 충돌 위험) |

## 3. 조도 센서 (`cds`)

- 밝은 실내 ≈ 400~700, 손/터널로 가리면 뚝 떨어짐.
- **절대값 기준 금지** — 조명마다 다름. 반드시 "현장에서 밝은 곳/어두운 곳 측정 → 사이값을 임계로" 방식.
- 측정값은 **짝수로 반올림**해 저장하는 관례 (사이값=평균이 항상 정수가 되어 초등생 계산 가능).
- 표시할 때 최소 30 보장 (`Math.max(30, cds)`) — 0이 뜨면 학생이 고장으로 오해.

## 4. 소리 (부저) — `state.soundSet(code)`

| 코드 | 37 | 39 | 41 | 42 | 44 | 46 | 48 | 49 |
|---|---|---|---|---|---|---|---|---|
| 계이름 | 도 | 레 | 미 | 파 | 솔 | 라 | 시 | 높은도 |
| Hz(참고) | 523 | 587 | 659 | 698 | 784 | 880 | 988 | 1047 |

- **끄는 걸 잊지 마세요**: `soundSet(code)` → 400~500ms 유지 → `soundSet(0)`. 안 끄면 계속 삑─.
- 멜로디는 음당 400~500ms 간격이 또렷함. 템플릿의 `playNote()`는 태블릿 스피커 동시 재생까지 포함
  (미연결 상태에서도 소리 확인 가능 — 수업 진행에 유용).
- 위 8개 코드 외 값은 음정 보장 안 됨 — 쓰지 마세요.

## 5. 도트매트릭스 (8×8) — ⚠ `state.dotOn` 직접 쓰지 말 것

**반드시 공용 모듈 `js/dotmatrix.js`(`window.AltinoDot`)를 쓰세요.**

이유(현장에서 두 번 헛짚고 확정한 사실): `state.dotOn(col, row)`에서
- `col` … 가로(왼→오). 예상대로 정상.
- `row` … **아래에서 위로 세는 번호!** (`row 1` = 맨 아랫줄, `row 8` = 맨 윗줄)

즉 세로축만 뒤집혀 있습니다. 이걸 모르고 찍으면 글자가 상하로 뒤집히고,
거기에 회전을 얹어 "고치려" 하면 좌우 거울상이 되어 더 알아보기 어려워집니다.

```js
const D = window.AltinoDot;
D.drawNumber(state, 14);              // 0~99 (십의 자리가 왼쪽)
D.drawGlyph(state, ['111','100','111'], 3, 2);   // 임의 비트맵 (논리좌표)
D.drawBytes(state, FONT.E);           // 8바이트 = 행(위→아래), 비트7=맨왼쪽
D.clear(state);                        // 지우기
```
- 좌표계는 **논리좌표**: `x` = 왼→오(1..8), `y` = **위→아래**(1..8). 변환은 모듈이 처리합니다.
- 기본 방향은 현장 검증값(보정화면 '7번' = `dotOn(x, 9-y)`)으로 설정돼 있습니다.
- 기기·펌웨어 차이가 의심되면 `D.openCalibration({state, send})` 로 보정화면을 띄워
  'F'가 똑바로 보이는 방향을 고르면 저장됩니다(전 앱 공용, localStorage).
- 모드 주의: 점을 찍으면 자동으로 비트맵 모드. 밝기 모드(`display()`)와 동시 사용 불가.

## 6. LED — `state.ledSet(bitmask)` (0~65535)

- `ledSet(15)` = 전방 등 계열 점등(현장 확인), `ledSet(0)` = 끔.
- 세부 비트별 매핑은 미확인 — 15/0 두 값만 쓰는 걸 권장. 효과음처럼 잠깐 켰다 끄는 용도로.

## 7. 배터리 (`battery`)

- 정상 ≈ 760~800. **700 미만이면 낮음 경고** (템플릿에 내장).
- 배터리 낮으면 로봇이 먼저 연결을 끊음(status 19) — "자꾸 끊겨요"의 1순위 원인은 배터리.

## 8. 물리 특성 메모

- 26바이트 프레임을 10Hz로 계속 보내는 구조 — 마지막 프레임 상태가 유지됨
  (전송을 멈춰도 로봇은 마지막 명령대로 계속 달림 → 정지 프레임을 꼭 보내고 끝낼 것).
- 급격한 방향 전환을 매 프레임 반복하면 좌우 진동(와리가리) — 방향 결정은 '래치'하고
  조건이 풀릴 때까지 유지하는 패턴 권장 (사례집 참고).
