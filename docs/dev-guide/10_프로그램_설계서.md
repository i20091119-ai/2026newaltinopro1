# 10. 프로그램 설계서 — 알티노 로봇 학교 (학교자율시간 32차시)

> **상태: 임시안 (2026-10-02)** — 주제·배정은 바뀔 수 있다. 바뀌면 이 문서와
> `webapp/js/apps.js`(앱 목록)를 **같이** 고친다. 주제별 상세는 `docs/topics/tNN.md`.

## 1. 한눈에

- **대상**: 3~4학년군 (연결 교과의 성취기준이 `[4국…]`·`[4수…]` 형식 = 3~4학년군)
- **구성**: 32차시 → **주제 앱 15개** (`t01`~`t15`). 앱 하나가 보통 2차시.
- **흐름**: 입학하기 → 기초반 *알티노 깨우기* → 교과반 *함께 공부하기* → 어울림반 *축제와 졸업*
- **한 모둠 = 태블릿 1대 = 로봇 1대** (1:1 짝). 32차시 내내 아래 두 가지가 이어진다.
  - **모둠 알티노 이름** — t01 입학식에서 짓고, 모든 앱 상단에 뜬다
  - **성장기록부** — 앱마다 성취를 남기고, t15 졸업식에서 모아 졸업장을 준다

## 2. 차시 ↔ 앱 매핑

시간표의 활동 17줄을 앱 15개로 묶었다. 1차시짜리 두 줄(1·2차시)과 마지막 공연 두 줄(29~32차시)을
각각 한 앱으로 합쳤다 — **이 묶음이 맞는지 확인 필요** (§7-1).

## 3. 저자 배정 (제안)

반(대주제) 단위로 나누면 한 저자의 앱 5개가 같은 결을 가져 화면·말투가 자연스럽게 맞는다.

| 저자 | 맡는 앱 | 성격 | 주의할 앱 |
|---|---|---|---|
| **A** | t02 · t03 · t04 · t05 · t06 | 기초반 — 기능 하나씩 익히기 | **t05** LED 선행 실측 필요 (§4) |
| **B** | t07 · t08 · t09 · t10 · t11 | 교과반 — 센서로 교과 공부 | **t11** 시간 기반 이동 (§4) |
| **C** | t01 · t12 · t13 · t14 · t15 | 입학 + 어울림반 — 종합·행사 | **t13** 음성 인식, **t14** 이동, **t15** 성장기록부 모으기 |

C 의 부담이 가장 크다(선행 조건이 붙은 앱 2개 + 전체를 모으는 t15). 배정을 바꾼다면 t13 을 옮기는 게 첫 후보.

## 4. 실현 가능성 점검 — 실측 근거로

로봇이 보내는 센서는 **TOF 거리 6개(ir1~ir6) · 조도 · 배터리가 전부**다(`js/protocol.js` 수신 프레임).
**바퀴 회전 센서·자이로·바닥 선 센서·마이크는 없다.** 이 사실이 몇몇 주제를 가른다.

| 판정 | 앱 | 조건 / 근거 |
|---|---|---|
| ✅ 바로 가능 | t01 t03 t06 t08 t10 t12 | 이미 현장에서 검증된 기능만 쓴다 |
| ⚠ 조건부 | **t02** | 속도 250 아래는 **제자리에서 출발을 못 한다**(실측). kit 의 출발 킥(S4)이 해결해 주지만, '0~500' 을 그대로 보여 주면 학생이 "200은 왜 안 가?" — 오히려 좋은 탐구 거리. 킥을 끄면(`kick:false`) 그 현상을 직접 보여 줄 수 있다. **2m 정지선**: 바닥을 보는 센서가 없으니 학생이 **타이밍으로 멈추는 조종 도전**이 된다 |
| ⚠ 조건부 | **t04** | 음정이 실측된 건 **8음(도~높은도)뿐**. 곡은 이 범위 안이어야 한다(학교종·나비야 등 가능, 낮은 솔·반음 불가) |
| ⚠ 조건부 | **t09** | **자리마다 빛이 다르다**(창가). 밝은 곳·어두운 곳 차이가 120 미만이면 기준을 못 만든다(2026-09 파일럿). 자동 라이트는 실측된 LED 값 15 사용 |
| ⚠ 조건부 | **t11 · t14** | 회전 센서·자이로가 없어 **'한 칸'·'90° 회전'을 시간으로만** 만든다 → 배터리·바닥·로봇마다 오차. **로봇별 이동 보정**이 필요하다 → 공용 기능 후보(§7-4) |
| ❗ 선행 작업 | **t05** | LED 는 **값 15 = 전방등만** 확인됐다. 방향지시등·브레이크등이 어느 비트인지 **아무도 재 보지 않았다.** 개발 전에 16비트를 하나씩 켜서 기록해야 한다(03 문서 §6 절차) |
| ❗ 선행 작업 | **t13** | 로봇에 마이크가 없어 **태블릿 마이크**로 인식해야 한다. 안드로이드 WebView 는 웹 음성인식(SpeechRecognition)을 지원하지 않는 것으로 알려져 있다 — 태블릿에서 `'webkitSpeechRecognition' in window` 한 줄로 먼저 확인할 것. 없으면 **네이티브(Kotlin) 음성인식 브리지**를 새로 만들어야 하고(통합 담당자 작업 + 마이크 권한 + 기기에 따라 인터넷 필요), 대안은 '말 카드'(학생이 말하면 교사가 버튼으로 넣는 방식) |

> ⚠ 이 표의 '알려져 있다'는 실기에서 확인 전이다. **현장 조건은 가정하지 말고 확인한다** —
> 이 프로젝트에서 그걸 어겨 두 번 되돌렸다(04 사례집 #20·#21).

## 6. 앱을 넘나드는 데이터

```
t01 입학식 ──▶ kit.team.set('번개호')            모든 앱 상단에 👥 번개호
         └──▶ kit.record.add({title:'입학했어요'})
t02 … t14 ──▶ kit.record.add({title, detail, stars})   앱마다 성취 기록
t15 졸업식 ──▶ kit.record.list()  → 전부 모아 성장기록부·졸업장
```

- **앱끼리 서로의 저장값을 읽지 않는다**(`altino.tNN.*` 는 그 앱 것). 다른 앱의 데이터가
  필요하면 공용 키로 만들어 달라고 요청한다(01 문서 §5). 위 두 가지(모둠 이름·성장기록부)가 지금의 공용 데이터 전부.
- 저장은 **태블릿에** 된다. 수업 중 태블릿을 모둠끼리 바꾸면 기록이 섞인다 → 운영 수칙(14 문서).

## 7. 열린 결정 (통합 담당자 / 3인 회의)

1. **17줄 → 15앱 묶음** — 1·2차시를 t01 로, 29~32차시를 t15 로 합친 게 맞는가
2. **저자 배정** — §3 제안대로 갈지
3. **t13 음성 인식 방식** — 네이티브 브리지 / 말 카드 / 주제 조정
4. **t11·t14 이동 보정을 공용으로** — kit 에 '로봇별 한 칸·90° 시간 보정'을 넣을지(넣으면 t02 도 씀).
   각자 만들면 두 앱의 보정이 따로 놀고, 태블릿을 새로 깔면 날아간다(04 사례집 #25)
5. **t05 LED 실측** — 누가 언제
6. **최종 앱의 시작 화면** — 지금 APK 는 체험관 홈(`home.html`)으로 열린다. 로봇학교(`school.html`)를
   같은 APK 의 시작 화면으로 할지, 학교용 APK 를 따로 낼지
7. **여러 반이 같은 태블릿을 쓸 때** — 모둠 이름·성장기록부는 태블릿에 저장된다. 반이 바뀌면 기록이 겹친다.
   반별로 태블릿을 나눌지, 기록을 반 단위로 나눠 저장할지(kit 기능), 내보내기를 둘지 — t15 기획과 함께 정한다
