# 12. 안전 규약 — 로봇이 멈춰야 하는 모든 순간

> 아이들 책상 위에서 **진짜 로봇이 움직인다.** 여기 있는 규칙은 전부 2026년 9월 체험관 현장에서
> 실제로 일어난 일에서 나왔다. 규칙은 **`js/kit.js` 가 다 지켜 준다** — 앱은 kit 을 '쓰기만' 하면 되고,
> kit 을 **우회하는 순간** 규칙이 깨진다. 아래 '앱이 할 일'만 지키면 된다.

## 왜 이렇게까지 하나 — 로봇의 성질 하나

로봇은 **마지막으로 받은 명령을 계속 실행한다.** 태블릿이 "멈춰"라고 보내지 않으면, 화면이 꺼지든
앱이 넘어가든 계속 달린다. 그래서 '멈춤'은 우리가 **보내야** 생긴다. 아래 규칙은 전부 이 한 줄에서 나온다.

## 규칙 요약

| | 규칙 | 실제로 있었던 일 | kit 이 하는 것 | 앱이 할 일 | 시험 |
|---|---|---|---|---|---|
| **S1** | 화면을 벗어나면 **그 자리에서** 정지 | 패드를 누른 채 ← 홈을 누르면 로봇이 계속 달렸다(다음 틱을 기다리다 WebView 타이머가 멈춤) | blur·pagehide·숨김에서 즉시 정지 프레임 | 없음 | smoke S1 |
| **S2** | 창(모달)이 떠 있으면 움직이지 않음 | 충전소 문제를 푸는 동안, 에너지가 차는 순간 차가 튀어나갔다 | 연결창·확인창·도트 보정은 자동 차단 | **앱이 띄우는 창은 `kit.block(창)`** | smoke S2, t00 |
| **S3** | **누르는 동안만** 움직임 | 정밀주차 전진·후진이 "잘 안 먹었다" — 스크롤 상자 안, touch-action 없음, 미끄러지면 뗀 걸로 처리 | 포인터 캡처·touch-action:none, 창이 떠 있으면 눌러도 무시 | **패드는 `kit.hold`**, 패드를 `overflow:auto` 상자에 넣지 않기 | t00 S3 |
| **S4** | 느린 출발은 처음에 세게(킥) | 속도 250 은 제자리에서 모터가 못 이기고 안 돌았다 | 330 미만으로 출발하면 첫 180ms 만 400 | 없음 (현상을 보여 주려면 `kick:false`) | smoke S4 |
| **S5** | 자율 동작은 **`kit.run` 안에서만** | 정지 직후 다시 출발하면 옛 루프가 깨어나 두 루프가 모터를 다퉜다 / 정지를 눌렀는데 다음 단계가 이어져 뒤로 튀었다 | 실행마다 세대 번호, 정지하면 옛 루프는 스스로 물러남 | `while (r.alive())`, **`if (!await r.sleep(ms)) return;`** | smoke S5 |
| **S6** | 자율 동작 중 센서가 끊기면 정지 | 센서 신호가 끊겨도 옛값을 믿고 25초를 직진했다 | 1.2초 수신이 없으면 움직임 0 + 알림 | 없음 | smoke S6 |
| **S7** | 정지하면 부저도 끈다 | 소리 미션 중 정지하면 부저가 계속 울었다 | `stop()` 이 소리·재생 중 신호까지 끔, `beep()` 은 자동으로 꺼짐 | 소리는 `kit.beep`·`kit.signal` 로 | smoke S7 |
| **S8** | 전송 10Hz 고정 | 한 화면만 20Hz 로 남아 12대 동시 운영 때 명령이 씹혔다 | 100ms 고정 | 전송을 직접 하지 않기 | smoke S8 |

## 앱이 할 일 — 이것만 지키면 된다

```js
const kit = AltinoKit.create({ appId: 't07', title: '수학 시험 보는 날' });

// S3 조종 패드
kit.hold(document.getElementById('d-up'), () => kit.drive(300, 0), () => kit.drive(0, 0));

// S2 앱이 띄우는 창
kit.block(document.getElementById('quizModal'));

// S5 자율 동작
kit.run(async (r) => {
  while (r.alive()) {
    if (r.sensor.ir2 < 200) break;        // 작을수록 가깝다
    r.drive(300, 0);
    if (!await r.sleep(100)) return;      // ← 이 한 줄이 S5 의 핵심
  }
  r.drive(0, 0);
  kit.signal('success');
});

// S7 소리
kit.beep(44, 400);          // 400ms 뒤 자동으로 꺼짐
kit.signal('fail');         // 뜻이 있는 소리는 신호 사전으로 (05 §3)
```

## 하지 말 것 — 하는 순간 규칙이 깨진다

| 하지 말 것 | 깨지는 규칙 | 대신 |
|---|---|---|
| `setInterval` 로 프레임을 직접 보내기, `buildFrame`·`AltinoNative`·`AndroidBridgeTransport` 직접 쓰기 | S1 S2 S6 S8 전부 | `kit.drive` |
| `addEventListener('touchstart'/'mousedown'/'pointerdown')` 로 '누르는 동안' 만들기 | S2 S3 | `kit.hold` |
| `setTimeout` 사슬이나 직접 만든 `sleep` 으로 자율 동작 | S5 S6 | `kit.run` + `r.sleep` |
| `r.sleep()` 결과를 안 보고 다음 동작 | S5 (정지 후 '한 동작 더') | `if (!await r.sleep(ms)) return;` |
| `state.soundSet(코드)` 만 하고 끄지 않기 | S7 | `kit.beep(코드, ms)` |
| 기본 `confirm()`·`alert()` | (먹통 — 태블릿에서 창 없이 false) | `kit.confirm` / `kit.toast` |
| 조종 패드를 `overflow:auto`/`scroll` 상자 안에 두기 | S3 | 카드는 `overflow:hidden` |

`tools/check_contribution.mjs` 가 위 표의 대부분을 자동으로 잡는다.

## 시험이 '진짜로' 잡는지 확인했다

시험이 통과한다고 규칙이 지켜진다는 보장은 없다 — 시험이 엉뚱한 걸 보고 있을 수 있다(04 사례집 #37).
그래서 kit 의 규칙을 **하나씩 일부러 깨뜨려** 시험이 실패하는지 확인했다(변이 시험, 2026-10-02):

| 깨뜨린 것 | 실패한 시험 항목 |
|---|---|
| pagehide 정지 제거 (S1) | S1 화면을 벗어나면 그 자리에서 정지 프레임 |
| 확인창 차단 제거 (S2) | S2 확인창이 떠 있으면 멈춤 |
| 포인터 캡처 제거 (S3) | S3 떼면 정지 — 버튼 밖에서 손을 떼면 계속 달림 |
| 킥 제거 (S4) | S4 느린 출발은 처음에 세게 |
| 세대 비교 제거 (S5) | S5 옛 루프(+300)가 새 루프를 덮지 않음 |
| 센서 끊김 정지 제거 (S6) | S6 센서가 1.2초 끊기면 멈춤 |
| 정지 시 부저 끄기 제거 (S7) | S7 정지하면 부저도 꺼짐 |

kit 을 고치면(통합 담당자) 이 변이 시험을 다시 돌린다 — 06 문서 §6.
