# 06. 개발·제출·통합 매뉴얼

세 저자가 **각자 자기 복사본에서** 앱 5개를 만들고, **통합 담당자 한 명이** 받아서 합친다.
저자는 §1~4, 통합 담당자는 §5~6.

```
통합 담당자 ──시작 묶음──▶ 저자 A·B·C (각자 복사본)
                              │ t00 복사 → 개발 → 검사 통과
통합 담당자 ◀──제출물(자기 앱 파일만)──┘
   │ 다시 검사 → 넣기 → apps.js ready:true → 전체 시험 → 푸시 → APK → 태블릿 업데이트
```

---

## 1. 개발 환경 (처음 한 번, 15분)

필요한 것: **Node.js 20 이상**, 크롬(또는 엣지), 글 편집기(VS Code 권장). 로봇·태블릿은 없어도 된다.

```bash
# 시작 묶음(저장소)을 받은 폴더에서
npm install                          # 시험 도구(playwright) 설치 — node_modules/ 는 저장소에 안 올라간다
npx playwright install chromium      # 시험용 브라우저 (한 번)
node tools/serve.mjs                 # 개발 서버 → http://localhost:8099/t00.html
```

- 브라우저에서 열면 **가짜 로봇**(MockTransport)이 붙는다. 센서 값이 10Hz 로 들어오고, 상단 칩은 `🚗 데모`.
  화면·흐름·저장·안전 규칙은 전부 여기서 완성한다.
- 가짜 센서 값은 평소 고정(정면 ir2 = 280, 조도 약 500)이라 '벽 앞에서 멈추기' 같은 동작이 안 일어난다.
  **콘솔에서 값을 바꿔** 상황을 만든다:
  ```js
  ALTINO_MOCK = { ir2: 150 }            // 정면에 벽이 다가옴 (작을수록 가깝다)
  ALTINO_MOCK = { cds: 80 }             // 터널 안처럼 어두움 (어두울수록 작다 — 03 §3)
  ALTINO_MOCK = { battery: 650 }        // 배터리 낮음 (700 미만 → 칩이 빨강)
  delete window.ALTINO_MOCK             // 기본값으로
  ```
- 로봇에 무엇을 보내는지 보고 싶으면 개발자 도구 콘솔에서 `window.__ALTINO_LOG_TX = true`.
- **실기**(진짜 로봇)는 APK 로만 된다 — 브라우저는 로봇의 블루투스에 붙을 수 없다. 실기 확인은 §5 를 거쳐
  통합 담당자가 만든 APK 로 하거나, 통합 담당자에게 시험 빌드를 부탁한다.
- 파이썬이 있으면 `cd webapp && python3 -m http.server 8099` 도 된다. **파일을 더블클릭(file://)으로 열지 않는다**
  — 브라우저마다 글꼴·저장이 다르게 동작해 태블릿과 달라진다.

## 2. 새 앱 만들기 (10분)

t07 을 예로:

1. 복사 (번호만 바꾼다)
   - `webapp/t00.html` → `webapp/t07.html`
   - `webapp/js/t00.js` → `webapp/js/t07.js`
   - (패드가 있으면) `tests/t00.mjs` → `tests/t07.mjs`
2. `t07.html`: `<title>`, `<h1>` 제목(= `js/apps.js` 의 title), 마지막 `<script src="js/t00.js">` → `js/t07.js`.
   **★ 표시 구역(공통 스타일·상단바·스크립트 순서)은 그대로 둔다.**
3. `t07.js`: `AltinoKit.create({ appId: 't07', title: '…' })`. ✎ 구역을 자기 활동으로 바꾼다.
   필요 없는 견본 기능(음표 버튼 등)은 지운다.
4. `tests/t07.mjs`: 맨 위 `const APP = 't00'` → `'t07'`, 버튼 id 를 내 패드 id 로. 지운 견본 기능(음표·카운터 등)의 시험은 같이 지운다.
5. 기획서 `docs/topics/t07.md` 의 ✎ 칸을 채운다(11 문서 양식).
6. 그림·소리는 `webapp/assets/t07/` 에.

**만들어도 되는 파일은 이것뿐이다** (01 §2):
`webapp/tNN.html` · `webapp/js/tNN.js` · `webapp/assets/tNN/*` · `docs/topics/tNN*` · `tests/tNN.mjs`.
공용 파일(kit·견본·시험·검사기·체험관 앱·android)을 고치고 싶으면 → **요청**(01 §5). 고쳐서 내면 검사기가 ❌.

## 3. 제출물 검사 — 통과해야 제출한다

```bash
node tools/check_contribution.mjs t07
```

| 표시 | 뜻 | 할 일 |
|---|---|---|
| ❌ | 고칠 것 — 하나라도 있으면 제출 불가 | 메시지대로 고친다 |
| ⚠️ | 확인할 것 | 읽고 괜찮으면 그대로 (기획서 ✎·'확정 전' 경고는 제출 전까지 없앤다) |
| ℹ️ | 참고 (시험 통과 등) | — |

검사기가 보는 것:
1. 필수 파일 (`tNN.html` · `js/tNN.js` · `docs/topics/tNN.md`), 기획서의 남은 ✎ 와 상태(확정)
2. **공용 파일 지문** — 하나라도 바뀌었으면 ❌ (`tools/shared-files.json`)
3. 규칙 — `localStorage` 직접 사용, `confirm()/alert()`, 프레임 직접 전송, `__altinoKit`,
   `touchstart/mousedown/pointerdown` 직접 연결(→ ❌) / `soundSet` 직접, 실측 안 된 소리 코드,
   `while(true)`, 직접 만든 sleep, `overflow:auto`, 로봇학교 링크 없음(→ ⚠️)
4. 스크립트 순서·`#kitBar`·appId 가 파일 번호와 같은지
5. 이 앱 범위 밖에서 바뀐 파일 (git 이 있으면)
6. **시험**: `tests/smoke.mjs t07`(공통 안전 21개 — S1~S8·신호·저장) + `tests/t07.mjs`(내 앱)

> 검사기가 못 보는 것: **실기에서 로봇이 생각대로 움직이는지**, 문제은행의 학년 범위, 말투.
> 이건 기획서의 '실기 확인' 칸과 05 문서로 스스로 확인한다.

### 내 앱 시험(`tests/tNN.mjs`)에 넣을 것

- 패드가 있으면 **누르는 동안만 움직이고, 떼면(버튼 밖에서 떼도) 멈춘다** (t00.mjs 의 S3 시험을 그대로).
- 앱이 띄우는 창이 있으면 **창이 떠 있는 동안 움직이지 않는다** (S2).
- 핵심 흐름 1개 — 예: 문제를 맞히면 `kit.record` 에 한 줄 / 점수가 `kit.store` 에 저장되고 새로고침 후 이어짐.
- 시험이 **진짜로 잡는지** 한 번은 확인: 앱 코드를 일부러 틀리게 고쳐 보고 시험이 실패하는지 본 뒤 되돌린다(04 #37).

**② git 브랜치** — 저장소 접근 권한이 있으면 `author/<이름>` 브랜치에 자기 파일만 커밋해 푸시.

함께 보낼 메모 (기획서 맨 아래에 써도 된다):
- 검사기 결과 마지막 줄 (`결과: 통과 …`)
- 실기에서 확인한 것 / 못 한 것
- `js/apps.js` 에서 바뀌어야 할 값 (제목·차시가 바뀌었으면)
- 공용 파일 변경 요청이 있으면 (01 §5)

## 5. 합치기 · 배포 (통합 담당자)

### 5-1. 합치기 — 앱 하나씩

```bash
git status                                   # 깨끗한 상태에서 시작
unzip t07_제출_….zip -d /tmp/t07 && cp -r /tmp/t07/* .    # 또는 git checkout author/홍길동 -- webapp/t07.html …
node tools/check_contribution.mjs t07        # 저자 쪽에서 통과했어도 다시 (공용 파일이 그 사이 바뀌었을 수 있다)
```
1. 검사 통과 → `js/apps.js` 의 그 앱 `ready: true` (제목·차시 바뀐 것 반영).
2. 앱 하나마다 커밋: `t07: 수학 시험 보는 날 합침 (저자 홍길동)`.
3. 다섯 개쯤 모이면 전체 시험:
   ```bash
   node tests/pages.mjs                        # 모든 화면이 오류·404 없이 열리는가 (브라우저·태블릿 두 조건)
   for a in t01 t02 …; do node tools/check_contribution.mjs $a; done
   ```
4. **저장 이름 충돌 확인** — kit.store 를 썼다면 자동으로 안 겹친다. 그래도 한 번:
   `grep -rnE "altino\.[a-z]" webapp/js/t[0-9]*.js` 로 다른 앱의 이름을 직접 쓰는 곳이 없는지.

### 5-2. APK 만들기

- `webapp/` 이 바뀐 커밋을 푸시하면 GitHub Actions(`.github/workflows/android.yml`)가 APK 를 만든다(몇 분).
- 배포 브랜치(`claude/tablet-webapp-altino-control-l1pngm`)에 푸시한 빌드만 **Release `v1.0.<실행번호>`** 로 올라가고,
  태블릿의 **앱 안 '업데이트 확인'** 이 그걸 받아 간다. 다른 브랜치 빌드는 Actions 의 Artifacts 에만 남는다(시험용).
- **빌드는 '시작했다'가 아니라 '성공했다'를 확인한다** — 조용히 실패한 적이 두 번 있다(04 #34).
  Actions 에서 초록 ✓ 와 Releases 의 새 버전을 눈으로 확인.
- ⚠ 지금 APK 는 체험관 홈(`home.html`)으로 시작한다. 로봇학교(`school.html`)로 들어가는 길은 아직 없다 —
  10 문서 §7-6 결정 후 `MainActivity.kt` 시작 주소 또는 home 의 링크를 정한다.

### 5-3. 태블릿 업데이트 — 덮어쓰기만

- 태블릿에서 앱 홈 → **업데이트 확인** → 받기 → 설치. **기존 앱 위에 덮어쓴다.**
- **앱을 지우고 새로 깔지 않는다.** 지우면 그 태블릿의 저장(모둠 이름·성장기록부·보정값·로봇 짝)이 전부 사라진다.
  체험관에서 이걸로 보정값이 날아가 몇몇 차가 '뱅글뱅글' 돌았다(04 #25).
- 덮어쓰기가 되는 이유: 모든 빌드를 같은 키(`android/app/altino.keystore`)로 서명하고, 버전 번호가 실행번호로 계속 올라간다.
  **이 키 파일을 잃어버리면 모든 태블릿을 지우고 새로 깔아야 한다** — 저장소 밖에도 사본을 둔다.
- 설치된 버전은 홈 화면 왼쪽 아래 `v1.0.xx`.
- 기관 유선망에서 GitHub 이 막힐 수 있다 — 업데이트는 와이파이·핫스팟으로.

### 5-4. CI 가 깨지는 흔한 이유

| 증상 | 원인 | 처리 |
|---|---|---|
| `Failed to find package 'tools'` | 러너 이미지가 바뀜 | `packages: 'platform-tools'` (이미 반영, 04 #34) |
| `versionCode` 관련 null 오류 | Groovy 문법 | 빌드 번호는 android 블록 밖 변수로 (이미 반영) |
| 빌드는 성공인데 태블릿이 업데이트를 못 찾음 | 배포 브랜치가 아닌 곳에서 빌드 | 배포 브랜치에 푸시 |

## 6. kit·공용 파일을 고칠 때 (통합 담당자)

공용 파일은 15개 앱 전부가 쓴다. 한 줄이 15개 앱을 깬다.

1. 요청 메모(01 §5)를 받고, **정말 공용이어야 하는지** 먼저 본다.
2. 고친다. 기존 API 이름·동작은 바꾸지 않는다(추가만). 바꿔야 하면 `AltinoKit.VERSION` 을 올리고 13 문서에 적는다.
3. 시험 — 전부 통과해야 한다:
   ```bash
   node tests/smoke.mjs t00 && node tests/t00.mjs && node tests/pages.mjs
   node tests/mutation.mjs        # 안전 규칙을 하나씩 깨뜨려 시험이 잡는지 — 7/7 이어야 한다
   ```
   `mutation.mjs` 가 '자리 못 찾음'이라고 하면, kit 코드가 바뀌어 깨뜨릴 문자열을 못 찾은 것 — `MUT` 표를 새 코드에 맞게 고친다.
   **새 안전 규칙을 넣으면 smoke 에 시험 + mutation 에 변이를 함께 넣는다.** 시험만 넣으면 시험이 엉뚱한 걸 볼 수 있다(04 #37).
4. 합친 앱이 있으면 그 앱들도: `node tools/check_contribution.mjs tNN` (각자).
5. 지문 다시 찍기: `node tools/check_contribution.mjs --snapshot` → `tools/shared-files.json` 이 바뀐다.
6. 문서(12·13·05) 갱신 → 커밋 → **새 시작 묶음**을 세 저자에게. 저자는 공용 파일을 덮어쓰고(자기 tNN 파일은 그대로) 검사를 다시 돌린다.

지문을 다시 찍지 않으면 모든 저자의 검사가 ❌ '공용 파일이 바뀌었습니다' 로 막힌다.

## 7. 자주 묻는 질문

- **Q. 검사기가 '공용 파일이 바뀌었습니다' 라는데 손댄 적이 없어요.**
  → 편집기가 저장하며 줄바꿈(CRLF)·마지막 줄을 바꿨거나, 예전 시작 묶음이다. `git checkout -- <파일>` 로 되돌리거나 새 묶음의 그 파일로 덮어쓴다.
- **Q. 시험이 `playwright 가 없습니다` 로 멈춰요.** → §1 의 `npm install && npx playwright install chromium`.
  회사·학교 망에서 브라우저 받기가 막히면 이미 깔린 크롬을 쓴다: `CHROMIUM_PATH="C:\…\chrome.exe" node tests/smoke.mjs t07`.
- **Q. 브라우저에선 되는데 태블릿에서만 안 돼요.** → 대개 ① 기본 `confirm()`(태블릿에서 먹통) ② `file://` 에서 `fetch()`
  (JSON 을 못 읽음 → JS 파일로) ③ 화면 크기. 검사기가 ①을 잡는다. 04 사례집 '안전 편'.
- **Q. 속도·거리 기준은 몇으로?** → 03 실측표의 값을 쓴다. 표에 없으면 재고 기록한 뒤 쓴다(03 §6 절차).
- **Q. 내 앱만 쓰는 도우미 함수가 생겼어요.** → 자기 `tNN.js` 안에. 두 앱 이상이 쓰게 되면 요청(01 §5).
- **Q. 체험관 앱(mode1·tag·park)의 코드를 쓰고 싶어요.** → 그 파일을 고치지 말고 필요한 부분을 **복사**해 `tNN.js` 에.
  어디에 무엇이 있는지는 10 문서 §5 재사용 지도.
- **Q. 전송을 20Hz 로 올리면 반응이 빨라지지 않나요?** → 12대가 동시에 돌면 명령이 씹힌다. 10Hz 고정(S8).
