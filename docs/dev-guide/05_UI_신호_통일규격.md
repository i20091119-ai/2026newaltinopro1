# 05. UI·신호 통일 규격

15개 앱을 세 사람이 따로 만들어도 **학생에게는 한 앱처럼** 보여야 한다. 같은 소리는 같은 뜻,
같은 버튼은 같은 자리, 같은 말투. `t00` 을 복사하면 §1·§2 는 저절로 지켜진다 —
**§3 신호 사전과 §5 문제은행 규칙은 직접 지켜야 한다.**

| § | 무엇 | 저절로? |
|---|---|---|
| 1 | 화면 규격 (크기·색·글꼴·버튼) | t00 복사로 ○ |
| 2 | 상단바·공통 칩 | t00 복사로 ○ |
| 3 | **신호 사전** — 뜻이 있는 소리·도트 | ✗ 직접 |
| 4 | 말투·문구 | ✗ 직접 |
| 5 | **문제은행 양식** | ✗ 직접 |
| 6 | 저장 이름 공간·공용 데이터 | kit 이 ○ (규칙만 알면 됨) |
| 7 | 진행 흐름 표준 | ✗ 직접 |
| 8 | 조사(이/가, 와/과) | `kit.josa` |

## 1. 화면 규격

- 기준 화면 **1280×800 가로 고정** (체험관 태블릿). 페이지는 스크롤되지 않는다 — `body{height:100vh;overflow:hidden}`.
  넘치면 내용을 줄이거나 화면을 나눈다. 카드 안 스크롤이 꼭 필요하면 **조종 패드가 없는 카드만**(S3, 12 문서).
- 색은 t00 의 CSS 변수만 쓴다. 새 색을 만들지 않는다.

  | 변수 | 값 | 쓰임 |
  |---|---|---|
  | `--cream` | `#fff7ea` | 바탕 |
  | `--ink` · `--mut` | `#3a3230` · `#9b8f86` | 글자 · 흐린 설명 |
  | `--mint` | `#37c9ad` | **성공·출발·확인** |
  | `--coral` | `#ff7a86` | **정지·실패·지우기** (위험한 버튼) |
  | `--sun` | `#ffb23e` | 주의·보조 강조 |
  | `--blue` | `#5ea0ff` | 기본 버튼·링크 |
  | `--grape` | `#b085ff` | 특별(보너스·공연) |
  | `--line` · `--card` | `#f0e6d8` · `#fff` | 테두리 · 카드 |

- 글꼴 **Esamanru**(`webapp/fonts/`, 300·500·700). 다른 웹 글꼴을 불러오지 않는다(태블릿이 오프라인일 수 있다).
- 버튼 클래스: `.btn`(파랑) `.btn.mint` `.btn.coral` `.btn.sun` `.btn.ghost`(흰 바탕).
  **정지 버튼은 언제나 coral**, 출발은 mint.
- 터치 대상은 **최소 48×48px**. 조종 패드 버튼은 t00 크기(약 100×80) 이상.
- 화면 전환은 `.hidden` 클래스 토글. 페이지를 새로 여는 건 앱 사이 이동(← 로봇학교)뿐.
- 그림·소리는 `webapp/assets/tNN/` 에. 한 파일 300KB 이하 권장(APK 가 무거워진다).

## 2. 상단바·공통 칩

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ ← 로봇학교   🎯 앱 제목  (작은 설명)          👥 번개호  🚗 BF16  🔋 812  🔗 연결됨 │
└─────────────────────────────────────────────────────────────────────────────┘
   왼쪽: 앱이 채움                                  오른쪽: #kitBar — kit 이 채움
```

- 왼쪽: `<a href="school.html">← 로봇학교</a>` + `<h1>` 이모지 1개 + 제목. **제목은 `js/apps.js` 의 title 과 같게.**
- 오른쪽: `<div id="kitBar"></div>` 만 두면 kit 이 칩을 그린다. **칩을 따로 만들지 않는다.**
  - 👥 모둠 이름 (t01 에서 지은 뒤부터 보임) · 🚗 로봇 스티커 번호(브라우저에서는 `데모`)
    · 🔋 배터리(낮으면 빨강) · 🔗 연결 상태(누르면 연결창)
- 센서 값을 보여 주고 싶으면 **앱 화면 안에** 둔다(상단바에 칩을 더 넣지 않는다 — 15개 앱의 상단바가 같아야 한다).

## 3. 신호 사전 — 같은 소리는 같은 뜻

학생은 15개 앱을 오가며 소리로 결과를 알아챈다. 앱마다 '성공' 소리가 다르면 소리가 뜻을 잃는다.
**뜻이 있는 소리는 반드시 `kit.signal(이름)`** 으로 낸다. `kit.beep` 은 음 자체가 활동일 때(t04 노래, 경적)만.

| 이름 | 언제 | 소리 (코드·ms) | 도트 |
|---|---|---|---|
| `success` | 맞힘·도착·단계 통과 | 솔 → 높은도 (44·150, 49·300) | ✓ (`ok`) |
| `fail` | 틀림·실패 — **격려하는 장면에서만** | 미 → 도 (41·150, 37·300) | ✗ (`no`) |
| `notice` | 차례가 왔다·주목·시간 다 됨 | 라 짧게 (46·120) | 그대로 |
| `start` | 출발 직전 (GO!) | 도 미 솔 (37·100, 41·100, 44·200) | 그대로 |
| `caught` | 잡혔다·부딪혔다 (운동회 꼬리잡기) | 높은도 길게 (49·400) — 체험관 꼬리잡기와 같은 소리 | 그대로 |

- 정의는 `js/kit.js` 의 `SIGNALS`. **이름을 새로 만들거나 소리를 바꾸려면 요청**(01 §5) — 한 앱에서만 바꾸면 사전이 깨진다.
- 신호가 울리는 중에 `kit.stop()` 하면 소리도 같이 멈춘다(S7).
- 태블릿 스피커로도 같은 뜻을 주고 싶으면 화면 효과(색·이모지)로 한다. 소리 파일을 새로 만들지 않는다.

**도트 아이콘** (`kit.dot.icon`): `ok` ✓ · `no` ✗ · `ask` ? · `heart` ♥ · `smile` ☺. 숫자는 `kit.dot.number(0~99)`.
같은 뜻이면 같은 아이콘(맞힘 = ✓, 문제 냄 = ?).

**LED** (`kit.led`): 실측된 건 **15 = 전방등**뿐(03 §6). 다른 값은 실측하기 전에 쓰지 않는다.

## 4. 말투·문구

- 학생에게: **해요체, 짧게, 한 문장에 하나.** 이모지는 문장당 1개까지. 3~4학년이 읽는다 — 한자어 대신 쉬운 말
  (`측정값` → `잰 값`, `임계값` → `기준`, `초기화` → `처음부터`).
- 실패는 **격려 + 다음 행동**: "아깝다! 큰 수에서 작은 수를 빼 봐요" (✗ "틀렸습니다").
- 숫자에는 단위를 붙인다: `220` → `220 (가까울수록 작아요)`, `속도 300`.
- 버튼은 **동사로 끝나는 짧은 말**: `출발`, `멈춰`, `다시 하기`, `다음 →`. 같은 일은 같은 말(`처음부터` 와 `리셋` 섞지 않기).
- 연결 안내는 kit 의 문구를 그대로 둔다(체험관에서 다듬은 것 — "페어링 필요 없어요", 스티커 번호 `BF16`).
- 위험한 버튼(기록 지우기, 짝 해제)은 `kit.confirm({ danger: true })` 로 한 번 더 묻는다.
- 교사용 설명은 앱 안에 넣지 않고 운영 패키지(14 문서)에.

## 5. 문제은행 양식 — 수학 문제를 내는 앱 (t07·t08 등)

**먼저 `js/problems.js` 를 쓴다** (초1~중3 × 80문항, 정답 독립 검산 완료):

```js
const P = window.AltinoProblems;   // <script src="js/problems.js"></script> 를 kit.js 앞에
P.GRADE_ORDER;                     // ['e1','e2',…,'m3']
P.GRADE_LABELS.e3;                 // '초3'
P.GRADE_POOLS.e3;                  // [{ q: '12 × 3 = ?', a: 36 }, …]
```

직접 문제를 만들 때도 **같은 모양**(`{q, a}`)으로, 자기 `tNN.js` 안에 둔다. 규칙은 전부 실제로 틀렸던 것에서 나왔다(04 #11·#21·#33):

1. **답은 0 이상의 정수만.** 숫자 키패드에 `−` 가 없다(04 #11). 소수·분수 답도 금지. 문제 속에는 음수·분수가 나와도 된다.
2. **그 학년 1학기 범위.** 학년·학기 범위는 기억으로 정하지 말고 교육과정(성취기준)을 확인한다 —
   "일차함수는 2학기"라고 단정했다가 틀렸다(04 #21).
3. **학년 사이에 같은 문제 금지.** 학년을 낮춰도 같은 문제를 만나면 안 된다(중2·중3 에 글자까지 같은 문제가 5개 있었다).
4. **답이 문제에 보이는 문제 금지.** `1 : 4 = 1 : ?` 같은 것(실제로 5문항이 있었다).
5. **쉽게.** 체험·수업 활동이다 — 암산이나 한 줄 계산. 좌절시키지 않는다.
6. **검산.** 사람이 쓴 답을 믿지 않는다. `q` 를 코드로 다시 계산해 `a` 와 맞춰 보는 짧은 스크립트를 돌리고,
   기획서에 "검산함(방법)"을 적는다.
7. **조사.** 숫자 뒤 조사는 읽는 소리에 맞춘다(§8). 분수 `3/4` 는 '4분의 3' 으로 읽으니 **분자(3)** 기준 →
   `3/4과`(삼 → 받침 ○). 문제 문장에 조사를 붙일 땐 `kit.josa` 를 쓰거나 조사 없이 쓴다.
8. 지수는 위첨자(`2³`), 곱하기 `×`, 빼기 `−`(U+2212) — `problems.js` 와 같은 기호.
9. 입력창은 체험관 앱과 같게 `<input type="number" inputmode="numeric">` + `확인` 버튼(Enter 도 제출).

## 6. 저장 이름 공간·공용 데이터

모든 앱이 **같은 저장소**를 쓴다(APK 안에서 모든 화면이 한 출처). 이름이 겹치면 다른 앱의 값을 덮는다.

| 이름 | 누가 쓰나 | 읽기 |
|---|---|---|
| `altino.tNN.*` | 그 앱만 — `kit.store` 가 자동으로 붙인다 | 그 앱만 |
| `altino.team.name` | t01 (`kit.team.set`) | 모든 앱 (`kit.team.get`, 상단 칩) |
| `altino.record` | 모든 앱 (`kit.record.add`) | t15 (`kit.record.list`) |
| `altinoDotOrientV1` | 도트 방향 보정(`kit.dot.calibrate`) | kit |
| `altinoCalV1` · `altinoTagV1` · 짝 정보 | 체험관 앱·네이티브 | **건드리지 않는다** |

- 앱은 `localStorage` 를 직접 쓰지 않는다(검사기가 잡는다).
- **언제 저장하나**: 점수·단계가 바뀔 때마다 `kit.store.set`. 앱을 다시 열면 이어지게 한다.
- **처음부터** 버튼은 `kit.confirm` 으로 묻고 `kit.store.remove` — 다음 모둠이 새로 시작할 수 있게.
- 보정값(학생이 맞춘 기준 등)은 `kit.store.num(key, 기본, 최소, 최대)` 로 읽는다 — 저장값이 망가져도 범위 안의 값이 나온다.
  그리고 **기본값 자체가 현장에서 맞는 값**이어야 한다 — 저장값은 언젠가 날아간다(04 #25).
- 저장은 **그 태블릿에만** 있다. 앱을 지웠다 깔면 사라진다(06 §5).

## 7. 진행 흐름 표준

- **단계형 활동**: 화면 위쪽(상단바 아래)에 단계 표시 `① 알아보기 ② 해 보기 ③ 도전` — 지금 단계를 mint 로.
  `← 이전` 은 왼쪽 아래, `다음 →` 은 오른쪽 아래.
- **출발 연출**: 자율 동작 전에 `kit.signal('start')` + 화면에 `준비… 출발!` (약 1초) → `kit.run`.
  아이들이 손을 로봇에서 뗄 시간이다.
- **정지 버튼은 항상 보인다** — 자율 동작이 있는 화면에는 coral `■ 멈춰` 가 눈에 띄는 자리에.
- **끝**: 결과 화면(별 0~3개) + `kit.signal('success')` + `kit.record.add({ title, detail, stars })` 한 번.
  같은 활동을 여러 번 해도 기록부에는 **가장 좋은 결과 한 줄**만 남도록 앱이 판단한다(t15 가 모은다).
- **실패**: 다시 하기 버튼을 바로 옆에. 실패 횟수로 벌주지 않는다.

## 8. 조사 처리

화면 문구에 숫자·이름·번호가 들어가면 조사가 틀리기 쉽다(`BF12와`? `BF12과`?).

```js
kit.josa('BF12', '과와');   // 'BF12와' — 끝 글자 '2(이)' 는 받침 없음
kit.josa('번개호', '이가'); // '번개호가'
kit.josa('7', '을를');      // '7을'   — '칠'
// 쌍: '과와' '이가' '은는' '을를' (받침 있을 때 · 없을 때 순서)
```

- 숫자는 읽는 소리 기준(1 일·3 삼·6 육·7 칠·8 팔·0 영 = 받침 ○). 영어 끝 글자는 l·m·n·r 만 받침으로 본다.
- 학생이 지은 모둠 이름 뒤에는 **반드시** `kit.josa` (어떤 이름이 올지 모른다).
