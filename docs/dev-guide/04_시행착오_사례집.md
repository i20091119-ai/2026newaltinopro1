# 04. 시행착오 사례집 — 우리가 이미 밟은 지뢰들

형식: **증상 → 원인 → 해결(현재 규칙)**. 같은 지뢰를 다시 밟지 않기 위한 기록입니다.
"규약이 왜 이렇게 까다롭지?" 싶을 때 이 문서를 보면 이유가 있습니다.

## 통신 편

**1. 일부 로봇이 앱 스캔 목록에 안 뜸 (시스템 블루투스에는 보임)**
- 원인: 서비스 UUID 필터로 스캔했는데, 일부 로봇은 광고 패킷에 UUID를 안 실음.
- 해결: 필터 없이 스캔 후 이름 접두(ALTINO*)로 선별. → 네이티브에 반영 완료, JS는 신경 쓸 것 없음.

**2. 12대 동시 운영 중 절반이 연결 끊김**
- 원인 복합: LOW_LATENCY 스캔이 전파 점유 + 50ms(20Hz) 스트리밍 트래픽 + 재연결 5회 후 포기.
- 해결: BALANCED 스캔, **10Hz 고정**, 포기 없는 자동 재연결(2회부터 OS 배경 재연결). → **STREAM_MS=100 절대 유지.**

**3. 홈에서 연결했는데 다른 앱으로 이동하면 끊김/미승계**
- 원인: 앱이 진입 시 새로 connect()를 시도하거나 아무것도 안 함 (심화주차 앱에서 실제 발생).
- 해결: 모든 앱은 진입 시 `nativeStart()` — 살아있으면 adopt, 짝 있으면 그 로봇, 없으면 스캔.

**4. 학생이 옆 태블릿의 로봇에 연결해버림**
- 원인: 스캔 목록에서 아무 로봇이나 탭 가능했음.
- 해결: 1:1 짝 잠금 — 짝이 있으면 다른 로봇은 🔒 + 탭 무시, `🔓 짝 해제` 버튼으로만 변경.

**5. 연결 표시는 '연결됨'인데 로봇이 안 움직임**
- 원인: 반열림(좀비) GATT 링크 — OS가 끊김을 20초+ 동안 감지 못 함.
- 해결: 네이티브에 좀비 감지(송신 중 8초 무응답→강제 재연결) 내장. JS에서 할 일 없음.

**6. 연결 목록의 ⟨5DBA⟩가 로봇 스티커(BF16)와 달라 대혼란**
- 원인: MAC 뒤 4자리를 표시했는데 스티커는 BLE 이름 기반 번호였음.
- 해결: `stickerCode()`로 이름에서 번호 추출해 크게 표시. **MAC 전면 표시 금지.**

## 주행 편

**7. 코너에서 벽에 머리 박고 좌우로 와리가리**
- 원인 2중: (a) 임계값 조합이 잘못돼 '부드럽게 틀기' 분기가 죽은 코드였음 (b) 매 프레임 좌우 재판단 → 방향 뒤집힘 진동.
- 해결: 파생 임계값은 동적 계산(×0.55), 회피 방향은 **래치**해서 정면이 뚫릴 때까지 유지.
- 교훈: **방향 결정을 매 프레임 다시 하지 말 것.** 슬라이더 값이 바뀌면 파생 값도 따라 변하게.

**8. 측면을 긁으며 달리다 멈춤 — "측면 센서 고장?"**
- 원인: 센서는 정상. 감지 임계값(100)이 너무 낮아 코앞에서야 반응 → 보정이 늦음.
- 해결: 정면 감지 160으로 상향(현장 완주 검증), 측면 무효 시 전면 대각으로 폴백.
- 교훈: "센서 고장"으로 단정하기 전에 임계값을 의심. 진단용 **센서 점검 화면**(mode1 ⑥)을 활용.

**9. 코너에 대각만 끼었는데 후진을 안 함**
- 원인: 후진 판단이 전면 중앙(ir2)만 봄 — ir1=50인데 ir2=119라 안 걸림.
- 해결: 전면 3개 중 최솟값으로 판단 + 대각 끼임 임계 70 추가.

## 콘텐츠 편

**10. 도트매트릭스 숫자가 계속 깨져 보임 (⚠ 원격 오진 2회 — 꼭 읽을 것)**
- 증상: 숫자가 "14→41"로도 보이고, 회전을 바꿔도 계속 알아볼 수 없게 나옴.
- 1차 오진: "180° 뒤집힌 것" → 회전 추가. 2차 오진: "두 자리 순서 문제" → 자리 스왑.
  둘 다 **현상만 보고 좌표를 손댄 것**이라 근본 원인을 못 잡았다.
- **진짜 원인**: `state.dotOn(col,row)`는 "바이트=세로줄, 비트=가로줄"을 가정하지만
  실제 하드웨어는 **전치(transpose)** 돼 있다 — 프레임 바이트 b[11..18]이 **행**(위→아래),
  각 바이트의 **비트7(MSB)이 맨 왼쪽 열**. 축이 뒤바뀌었으니 어떻게 회전해도 글자가 안 맞는다.
- **확인 방법(결정적 증거)**: `code.js`의 배송문자 FONT(N/E/D/W/S)를 "바이트=행, 비트7=왼쪽"으로
  읽으면 다섯 글자 모두 완벽한 글자로 렌더된다. 즉 그 해석이 하드웨어의 진짜 매핑이다.
  → `dotOn(c,r)`은 물리적으로 (행=9−c, 열=9−r)을 켠다. 논리(x,y)를 바르게 찍으려면 `dotOn(9−y, 9−x)`.
- **해결**: `js/dotmatrix.js` 공용 모듈. 논리좌표(x=왼→오, y=위→아래)로만 그리고 변환은 모듈이 처리.
  자리 순서 문제도 논리좌표에선 구조적으로 발생하지 않아 스왑 꼼수가 사라졌다.
  혹시 모를 개체 차이는 **방향 보정 화면**(F 글자 보고 8방향 중 선택→저장)으로 현장에서 해결.
- **교훈**: ① `state.dotOn`을 직접 쓰지 말 것(반드시 `AltinoDot` 경유).
  ② 표시 문제를 좌표 조정으로 "맞춰보는" 대신, **이미 정상 동작하는 데이터(FONT)를 역산**해
  매핑을 확정할 것. ③ 원격에서 사진만으로 두 번 틀렸으면 추측을 멈추고 보정 도구를 만들 것.

**11. 답이 음수인 수학 문제 — 입력 불가**
- 원인: 숫자 키패드(inputmode=numeric)에는 마이너스가 없음.
- 해결: 문제은행 규칙 — **답은 항상 0 이상의 정수.** (문제 지문에는 음수 사용 가능)

**12. 연결 끊겨 앱 재시작 → 학생이 모은 점수·진행 증발, 대실망**
- 해결: 진행 상태를 localStorage에 저장(변경 시점마다 + 2초 주기 + 화면 이탈 시), 재시작 시 자동 이어가기.
- 교훈: **부스/교실 앱에서 진행 상태 저장은 선택이 아니라 필수.**

**13. 소리 안 꺼짐 / LED 잔류 / 멈췄는데 계속 달림**
- 원인: 프레임 스트리밍 구조상 마지막 상태가 유지됨.
- 해결: 활동 종료·이탈 시 `state.stopAll()` + 마지막 프레임 전송. 소리는 켠 뒤 반드시 `soundSet(0)`.

**14. 센서 숫자가 덜덜 떨려 정신없음**
- 해결: UI 갱신 200ms 스로틀 + 고정폭 숫자칸(`tabular-nums`, `min-width`). 표준 패턴.

**15. 태블릿마다 화면이 잘리거나 스크롤 생김**
- 해결: 1280×800 가로 기준, `overflow:hidden` 레이아웃, 검증 스크립트에 오버플로 검사 포함.
- 교훈: 절대 위치·고정 픽셀 남발 금지, flex/grid로. 요소가 많으면 카드 내부만 스크롤.

## 운영 편 (앱 밖이지만 알아둘 것)

**16. "오케스트라 앱은 잘 됐는데" — 알고 보니 같은 BLE**
- 원본 오케스트라 앱을 리버스 엔지니어링해 같은 전송(ISSC UART)·같은 프레임을 확인.
  체감 차이는 재연결 전략 차이였고 지금은 동등. 통신 스택을 의심하기 전에 환경(아래)을 볼 것.

**17. 현장 끊김의 진짜 3대 원인**
- ① 로봇 배터리(<700) ② 2.4GHz 혼잡(태블릿 Wi-Fi는 5GHz로) ③ 거리/사람 차폐.
- 코드가 아니라 운영으로 잡는 문제. 학생 안내문에 반영해 둘 것.
