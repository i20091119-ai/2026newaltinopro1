# 01. 아키텍처 개요

## 1. 전체 구조

```
┌──────────────────────────── APK (Android WebView 래퍼) ────────────────────────────┐
│ MainActivity.kt ─ WebView 전체화면 · 화면 꺼짐 방지 · 권한 · 뒤로가기=웹 뒤로        │
│ AltinoBle.kt ──── BLE 브리지: 스캔·연결·1:1 짝·포기 없는 재연결·좀비링크 감지         │
│ AltinoUpdate.kt ─ 앱 안 업데이트(GitHub Releases)                                  │
│        ↕ window.AltinoNative                                                    │
│ ┌──────────────────────── webapp/ (순수 HTML+JS, 빌드 없음) ───────────────────┐ │
│ │ school.html ── 알티노 로봇 학교 (주제 앱 목록 화면)  ← js/apps.js 를 읽음     │ │
│ │ t01.html … t15.html + js/t01.js … t15.js ── 주제 앱 15개 (저자 3명)          │ │
│ │ t00.html + js/t00.js ── 견본 앱 (복사의 원본)                                │ │
│ │ ── 공용 ──────────────────────────────────────────────────────────────── │ │
│ │ js/kit.js ────── ★ 주제 앱 실행 틀: 연결·안전·저장·신호 (12·13 문서)          │ │
│ │ js/protocol.js ─ 26바이트 송신 / 54바이트 수신 프레임                           │ │
│ │ js/transport.js  네이티브 브리지 · 가짜 로봇(브라우저)                         │ │
│ │ js/ui.js ─────── 확인창   js/dotmatrix.js ─ 도트(방향 보정)                   │ │
│ │ js/problems.js ─ 학년별 문제은행 720문항                                     │ │
│ │ ── 체험관 현장 앱 (검증 끝, 주제 앱 작업에서 건드리지 않음) ──────────────── │ │
│ │ home.html · mode1.html(자율주행) · tag.html(꼬리잡기) · park.html(정밀주차)   │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────────────┘
tests/  smoke.mjs(공통 안전) · tNN.mjs(앱별) · pages.mjs(전 화면) · mutation.mjs(시험의 시험) · stub.js(가짜 네이티브)
tools/  check_contribution.mjs(제출물 검사) · shared-files.json(공용 파일 지문) · serve.mjs(개발 서버)
        make_pdf.mjs(활동지 PDF·장수 확인) · make_worksheet_pptx.py(활동지 PPT 견본)
docs/   dev-guide/(이 가이드) · topics/tNN.md(주제별 기획서)
```

- **프레임워크 없음.** 순수 HTML + JS + 인라인 CSS. 파일이 곧 앱.
- 주제 앱 하나 = **HTML 1개 + JS 1개**(+ 필요하면 그림·소리 폴더). JS 는 IIFE `(function(){…})()` 로 감싼다.
- 로봇은 **kit 으로만** 움직인다. 앱은 `AltinoNative`·`transport`·`buildFrame` 을 직접 만지지 않는다.

## 2. 파일·이름 규칙

| 무엇 | 규칙 | 예 (t07) |
|---|---|---|
| 화면 | `webapp/tNN.html` | `webapp/t07.html` |
| 로직 | `webapp/js/tNN.js` | `webapp/js/t07.js` |
| 그림·소리 | `webapp/assets/tNN/` | `webapp/assets/t07/race.png` |
| 앱 저장값 | `kit.store` → `altino.tNN.이름` (자동) | `altino.t07.best` |
| 기획서 | `docs/topics/tNN.md` | |
| 활동지·강사용 | `docs/topics/tNN_활동지.*` · `tNN_강사용.*` (14 문서) | `t07_활동지.pptx` |
| 앱 시험 | `tests/tNN.mjs` (패드가 있으면 필수) | |
| kit 의 appId | 파일 번호와 같게 | `AltinoKit.create({ appId: 't07' })` |

**저자가 만드는 파일은 위 표의 것뿐이다.** 다른 파일이 바뀌어 있으면 제출물 검사기가 경고한다.

## 3. 공용 파일과 소유

| 구역 | 파일 | 누가 |
|---|---|---|
| 🔒 kit·공용 JS | `js/kit.js` `protocol.js` `transport.js` `ui.js` `dotmatrix.js` `problems.js` | **통합 담당자만** |
| 🔒 앱 목록·학교 화면 | `js/apps.js` `school.html` | 통합 담당자 (합칠 때 `ready:true`) |
| 🔒 견본·시험·검사기 | `t00.*` `tests/stub.js` `smoke.mjs` `pages.mjs` `mutation.mjs` `t00.mjs` `tools/*` `package.json` | 통합 담당자 |
| 🔒 네이티브 | `android/` 전체 | 통합 담당자 — BLE 는 12대 현장 검증 상태 |
| 🔒 체험관 현장 앱 | `home` `mode1` `tag` `park` `index` + 그 JS | 손대지 않음 (가져다 쓸 코드는 **복사**해서 자기 tNN.js 에) |
| ✎ 자유 | 자기 `tNN.*`, `assets/tNN/`, `docs/topics/tNN*`, `tests/tNN.mjs` | 저자 |

공용 파일 전부의 지문이 `tools/shared-files.json` 에 있어서, 하나라도 바뀌면 검사기가 **❌**로 잡는다
(줄바꿈 CRLF/LF 차이는 무시한다 — 윈도우에서 받아도 된다).

## 4. 개발 · 통합 흐름

```
통합 담당자: 시작 묶음 배포 (이 저장소 그대로 — kit·견본·시험·검사기·기획서 초안)
   │
   ├─ 저자 A: t02~t06 ─┐
   ├─ 저자 B: t07~t11 ─┼─ 각자 자기 복사본에서 개발 → check_contribution 통과 → 제출(브랜치 또는 zip)
   └─ 저자 C: t01,t12~15┘
   │
통합 담당자: 제출물 하나씩 → 검사기 다시 돌림 → 복사해 넣음 → apps.js ready:true → 전체 시험 → 빌드
```

자세한 절차는 06 문서.

## 5. 공용 파일 변경 요청 · 공용 데이터 요청

kit 에 없는 기능이 필요하거나, 다른 앱과 데이터를 나눠야 할 때.

1. **먼저 자기 tNN.js 안에서 해결할 수 있는지** 본다. 한 앱만 쓰는 기능은 그 앱에 둔다.
2. 두 앱 이상이 쓰거나, 안전 규칙(12)에 걸리면 → 통합 담당자에게 **요청 메모**:
   - 무엇이 필요한가 (함수 이름·동작 한 줄)
   - 어느 앱이 쓰는가
   - 지금은 어떻게 버티고 있는가
3. 통합 담당자가 kit 에 넣고 → `tests/mutation.mjs`·`smoke.mjs` 통과 → 지문 다시 찍기 → **새 시작 묶음**을 세 저자에게.
4. 저자는 새 묶음의 공용 파일로 **덮어쓴다**(자기 tNN 파일은 그대로).

현재 알려진 요청 후보: **로봇별 이동 보정**(t02·t11·t14, 10 문서 §7-4), **음성 인식 브리지**(t13).

**공용 데이터**는 지금 두 가지뿐이다 — 모둠 이름(`kit.team`), 성장기록부(`kit.record`).
다른 앱의 `altino.tNN.*` 를 직접 읽지 않는다. 필요하면 위 절차로 공용 키를 만든다.

## 6. 왜 이렇게 생겼나

1. **안전 규칙을 kit 한 곳에** — 9월에 잡은 '로봇이 안 멈추는' 버그 5종이 8월 템플릿에 그대로
   남아 있었다. 15개 앱이 각자 복사하면 언젠가 하나는 빠진다. 한 곳에 두고 시험으로 지킨다.
2. **연결은 네이티브가 주인** — 페이지를 옮겨도(학교 화면 ↔ 앱) 블루투스 연결이 살아 있고,
   새 화면은 이어받기만 한다. 앱이 연결을 각자 관리하면 반드시 깨진다(04 #3).
3. **앱 목록이 JSON 이 아니라 JS** — 태블릿은 `file://` 로 열리는데 WebView 는 거기서
   `fetch()` 로 JSON 을 못 읽는다. `<script>` 로 싣는 건 된다.
4. **목록·학교 화면을 한 파일로** — 15개 앱이 각자 홈 화면을 고치면 합칠 때마다 충돌한다.
5. **10Hz 스트리밍** — 로봇은 최신 상태 프레임을 계속 받는다. 앱은 '무엇을 하라'만 정하고 전송은 kit 이.
