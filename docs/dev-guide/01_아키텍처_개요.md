# 01. 아키텍처 개요

## 전체 구조

```
┌─────────────────────────── APK (Android WebView 래퍼) ───────────────────────────┐
│  MainActivity.kt ── WebView 전체화면, 화면 꺼짐 방지, BT 권한                      │
│  AltinoBle.kt ───── BLE(GATT) 브리지: 스캔·연결·1:1짝·자동재연결·좀비링크 감지     │
│         ↕ window.AltinoNative (JS 브리지)                                        │
│  ┌──────────────────────── webapp/ (순수 HTML+JS, 프레임워크 없음) ────────────┐  │
│  │  home.html ──── 런처 (각 앱으로 이동하는 홈 화면)                            │  │
│  │  t01.html … t15.html ──── 앱 15개 (앱마다 HTML 1개)                         │  │
│  │  js/t01.js … t15.js ───── 앱별 로직 (앱마다 JS 1개)                         │  │
│  │  js/protocol.js ──── [공유] 26바이트 프레임 인코딩·54바이트 센서 파싱        │  │
│  │  js/transport.js ─── [공유] 전송 계층 (네이티브 브리지·목·WS)               │  │
│  │  js/problems.js ──── [공유] 문제은행 (쓰는 앱만 로드)                       │  │
│  └────────────────────────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- **프레임워크 없음** (React/Vue 없음). 순수 HTML + JS + 인라인 CSS. 빌드 과정 없이 파일이 곧 앱.
- 앱 1개 = **HTML 1개 + JS 1개**. 전부 IIFE `(function(){ ... })()` 로 감싸 전역 오염 금지.
- 로봇 통신은 전부 네이티브(APK)가 담당. JS는 `window.AltinoNative`를 `transport.js`를 통해서만 사용.

## 파일·이름 규칙

| 항목 | 규칙 | 예 |
|---|---|---|
| 앱 파일 | `t<번호2자리>.html` + `js/t<번호2자리>.js` | `t07.html`, `js/t07.js` |
| 주제 배정 | 저자A: t01~t05, 저자B: t06~t10, 저자C: t11~t15 | |
| localStorage 키 | `altinoT<번호>V1` (버전 올리면 V2) | `altinoT07V1` |
| 홈 등록 | `home.html`에 카드 한 개 추가 (머지 때 일괄) | |

## 수정 금지 / 자유 구역

| 구역 | 파일 | 규칙 |
|---|---|---|
| 🔒 공유층 | `js/protocol.js`, `js/transport.js` | **수정 금지.** 수정 필요 시 3인 합의 → 1명이 수정 → 전 앱 회귀 확인 |
| 🔒 네이티브 | `android/` 전체 | 동일. 특히 `AltinoBle.kt`는 12대 현장 검증 완료 상태 |
| 🔒 앱 내 ★공통 구역 | 각 앱 JS의 연결/스캔/스트리밍 부분 | 템플릿에서 복사한 그대로 유지 (전 앱 동일해야 함) |
| ✎ 자유 | 각 앱의 ✎ 구역, 자기 HTML | 마음껏 |

## 왜 이렇게 생겼나 (설계 배경 3가지)

1. **WebView + 순수 JS**: 교사가 유지보수할 수 있고, 브라우저만으로 로봇 없이 개발 가능(목 모드).
2. **연결 로직이 네이티브에 있는 이유**: 페이지를 이동해도(홈↔앱) GATT 연결이 살아있고,
   JS는 `getState()→adopt()`로 이어받기만 한다. 앱 15개가 연결을 각자 관리하면 반드시 깨진다
   (실제로 심화주차 앱에서 이 패턴을 빼먹어 "연결이 안 이어져요" 사고 발생 — 사례집 참고).
3. **10Hz 스트리밍 모델**: 로봇은 "최신 상태 프레임"을 계속 받는 구조라서, 조작 코드는
   state만 바꾸면 되고 전송 타이밍·유실 걱정이 없다.
